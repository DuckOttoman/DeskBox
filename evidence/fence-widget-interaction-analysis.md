# FenceBox and WidgetBox interaction evidence

The recovered original Vue frontend has independent custom menus for FenceBox and WidgetBox. Neither uses Windows shell context menus. FenceBox offers title rename, search within the box, collapse/expand, style panel, name sort, hide, and a delete confirmation submenu (items move into Other). WidgetBox offers an opacity submenu with 35%, 60%, 85%, 100%, and remove widget. The original frontend action handlers remain in the compiled assets.

The native reconstruction previously attached its overlay as WS_CHILD to WorkerW/Progman before calling Tao show(). Tao reapplies a cached top-level window style on visibility/focusability changes. The desktop-parented regression test reproduced a lost WS_CHILD/parent (`smoke-interaction-red/runtime.log`). Production now finishes Tao show before native parenting and does not call Tao set_focusable/set_focus for desktop editors. Keyboard focus is dispatched on the WebView UI thread, using native style changes, root activation, SetFocus and WebView2 MoveFocus. GetFocus is checked against the target window and its children. There is no Tao global Alt-input fallback.

The desktop interaction fixture uses actual recovered Vue DOM and real backend persistence with isolated files/config. It checks desktop parent/style through original menu actions, frame collapse/search/title/style persistence, widget opacity submenu/checkmark/removal, and actual native focus ownership. DOM mouse/key events drive the test; this does not establish every physical dragging, resizing or multi-monitor interaction.

A second native failure exposed the former wallpaper-style host lookup: the next WorkerW sibling was invisible on this machine. Interactive overlays now use the visible WorkerW/Progman containing SHELLDLL_DefView, and startup errors if no such host exists. Native attachment checks also reject invisible parents. Focus success checks both foreground root and focused child ownership; failed focus restores NOACTIVATE.
