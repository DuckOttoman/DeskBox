# 分类学习、拖动和显示器审计（2026-10-10）

重建工程依据原二进制证据实现，并非恢复出的原始 Rust 源码。

## 学习逻辑证据

- 0x140175134–0x14017517e：目标转小写；0x140174372–0x1401744a1：斜杠归一、取最后段，构造 `t:程序名.exe`，保留扩展名。
- 0x140173749：读取 URL=；0x1401737df–0x14017382b、0x1401744c7–0x140174504：网址转小写并构造 `u:完整网址`。
- 0x140173300–0x140173369、0x140174a25–0x140174a5b：无目标和网址时使用 `n:显示名称`。
- 每个项目仅生成一个键：目标优先，其次网址，最后名称。键保存在项目 +0x90，指针/长度 +0x98/+0xa0。
- 整理调用 0x14017829a；0x1401782fb–0x140178311 查学习映射，未命中时 0x1401783e6–0x1401783f7 返回扫描分类。
- 移动调用链 0x1401f3fac→0x1401f4d6b→0x1401faf3c→0x1401ffd1d；0x1401ffe8a–0x1401ffe97 复制缓存键。0x14020008a 忽略无分类框，0x1402000db–0x1402000f2 忽略 inbox，其余写入并替换映射。移动不改缓存分类。

扫描 `.lnk`/`.url`、整理查表和移动写入现共用该键，缓存键不发送到前端。刷新比较包含内部键，避免目标改变而可见字段不变时丢弃更新。URL BOM 兼容属于实现扩展。

## 显示器与拖动

原前端 OverlayView（可读提取稿 7509–7516）将断屏对象显示到主屏；拖动保存（6363–6397、7073–7112）仍带原 monitor。此前后端拒绝这个保存，现允许已有对象保留断屏归属，仍拒绝全新的未知显示器。

负坐标及物理像素到显示器局部逻辑单位的转换有核心测试。原前端图标拖放、标题移动、吸附和调整大小代码保留；没有证据证明原版支持跨独立显示器 WebView 图标拖放，未添加推测功能。

`--drag-session` 独立窗口只扫描测试文件，不隐藏真实桌面图标。真实鼠标验证受到当前用户输入和透明窗口命中范围干扰，未得到可重复受控结果，不计为通过。双屏不同 DPI、热插拔、实际桌面父窗口中的完整拖动和缩放仍需实测。

只读复核未发现阻塞问题。原版全部分类词库、版本信息识别和完整整理布局仍未完全恢复，不能声称全面一致。
