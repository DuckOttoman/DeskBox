# 原版与重建版行为差异核查

状态：**未达到原版功能等价，不能称为完整逆向成果。**

依据：读取本机原版和重建版的配置；检查原始 PE 的资源、分类相关字符串和反汇编引用；对照重建实现。只读检查原版，不修改原版配置。下述配置比较描述当前用户状态，不等同于原版出厂默认值。

## 修正前确认的差异（历史记录）

| 项目 | 原版证据 | 当前重建实现 | 影响 |
|---|---|---|---|
| 文件 ID | 194 个普通文件 ID 全部等于规范化 Windows 路径的小写形式；系统项为小写 shell GUID 路径 | scanner::stable_id 使用 16 位 FNV 哈希 | 原配置的分配 ID 无法对应；两个配置的 ID 交集为 0 |
| 配置版本 | 原配置包含 version: 1 | Config 不包含 version | 不能完整往返原版配置 |
| 手动学习 | 原配置的 3 条记录均为 n: 加小写显示名；原 PE 有 t:/u:/n: 格式常量，被扫描函数引用 | name:/ext:/path:，部分文件按扩展名共享学习 | 旧学习记录不生效，手动调整的影响范围不同 |
| 当前主题和行为设置 | 原版 neon、隐藏桌面图标开启、监控间隔 1000ms | 重建版 glass-dark、隐藏桌面图标关闭、监控间隔 2000ms | 用户看到的外观和行为不同；未沿用原版状态 |
| 当前组件 | 原配置 2 个组件，含位置和样式 | 重建配置 0 个组件 | 原有组件未保留 |
| 当前分类结果 | 原配置 195 个项目，其中 tools 49、other 2 | 重建配置 197 个项目，其中 tools 18、other 35 | 数量不是同一时刻的严格对照，但已说明原分类分配没有保留；仍需同输入运行比较 |
| 分类信息来源 | PE 导入 GetFileVersionInfoSizeW/GetFileVersionInfoW/VerQueryValueW；CompanyName、FileDescription 在扫描函数内有引用 | 不读取版本资源；仅用名称、快捷方式目标和扩展名 | 软件识别缺少原版信号 |
| 游戏协议和安装路径 | 原扫描函数引用 10 条协议和 36 条路径特征，已定位原始表 | 未作为独立判断阶段实现 | 某些游戏/启动器分类不一致 |
| 默认整理布局 | 当前原配置中的框为 300 宽并有用户保存的高度、位置 | 首次/完整整理使用 320 宽的重建网格 | 布局算法未证明等价；保存状态也未沿用 |

## 定位到的原版机器码

- 扫描/分类相关函数范围：0x140172700–0x14017562c。
- CompanyName 引用：0x140173c7e；FileDescription 引用：0x140173da5。
- 游戏协议表引用：0x1401741b7；路径特征表引用：0x1401746df。
- t:/u:/n: 格式常量引用：0x140174492、0x1401744fd、0x140174a4c。
- 协议表原文件偏移：0x3e5d48，共 10 个字符串切片。
- 路径表原文件偏移：0x3e5f38–0x3e6178，共 36 个字符串切片。

反汇编和引用证据：original-scanner-disassembly.txt、original-app-xrefs.json、original-learning-xrefs.json。常量存在及代码引用不能单独证明所有分支优先级；需要继续追踪控制流或原版同输入运行验证。

## 现有测试的实际证明范围

现有测试证明重建代码可编译、若干状态操作自洽，以及新增重命名接口能运行。它们没有把原版当作行为对照，所以**不能证明重建版与原版等价**。隐藏窗口测试也没有验证真实桌面挂接、屏幕热插拔或完整文件操作。

## 后续修正顺序

1. 先复现用户指出的具体差异，记录原版操作与结果。
2. 恢复路径 ID、配置版本及学习键兼容，保留旧布局、主题、组件和背景；迁移时备份重建配置，原版保持只读。
3. 按实际控制流恢复协议、路径、版本信息和词库判断，使用相同输入比较分类结果。
4. 对桌面挂接、拖动/吸附、悬浮球、显隐和多屏分别做原版对照。
5. 保留新增重命名，但只在对照通过后交付更新，并逐项列出仍未确认的行为。
