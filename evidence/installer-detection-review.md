# Installer detection correction (2026-10-15)

Observed failure: the current-user uninstall entry pointed to a stale D: directory lacking deskbox-reconstructed.exe, while a valid rebuilt application existed in the conventional C: per-user DeskBox folder. Previous initialization used the registration string without checking that the executable existed and did not present existing installation/component status.

The installer now uses a read-only inventory shared by initialization, the post-directory summary page, runtime checks and CPU-service activation decisions. It reads both registry hives/views, prefers candidates with the actual rebuilt executable, falls back to known per-user/program folders, distinguishes residual registration, and preserves explicit /D using GetCommandLineW because NSIS removes /D from its processed command line. Original deskbox.exe is not treated as the rebuilt application. Arbitrary drives are not recursively scanned.

Payload hash manifest generated from the release identifies matching, missing/incomplete or differing application/FFmpeg/sensor components. Hashes are calculated using direct managed SHA256, avoiding a PowerShell cmdlet failure observed specifically inside the compiled installer that initially marked all files as differing. WebView uses valid registry versions across views; PawnIO version and protected service image/payload are checked. Equivalent Windows path separators are normalized for service comparison. A healthy matching global service skips redundant UAC. This does not claim complete WebView/PawnIO functional or corruption diagnosis.

Independent review caught explicit /D edge cases and false success on diagnostic report copy failure. Both were fixed; compiled probes verify stale-registered and default explicit destinations remain selected while automatic detection selects the actual installation. Pure policies cover residual/fresh/valid candidates, healthy/changed/missing file groups, versions and normalized service images. Final independent review found no remaining blocker. Native compiled read-only probes confirm complete release directory components are all recognized and global service is ready. Normal app files/configuration/registration were not modified. Isolated installer regression validates install/upgrade/locked application rejection/media UI/uninstall/user-data retention.

The new detection page was compiled but not separately visually pixel-reviewed. Missing-WebView clean VM and arbitrary other-user installations were not physically tested. No GitHub upload.
