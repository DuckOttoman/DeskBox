# Native quickbar ownership implementation

Files: src/taskbar.rs; tests/taskbar-policy.rs.

API: taskbar_monitors(&[Monitor]) -> Vec<Monitor>; fullscreen_on(&Monitor) -> bool; recover_stale(&Path) -> Result<(), String>; watchdog_main(&[String]) -> Option<i32>. Call watchdog_main before Tauri plugins and exit if Some. Controller::enable(directory, &[(HWND, Monitor)]) -> Result<Controller,String>; tick() -> Result<Vec<(monitor_label, should_show)>,String>; disable() (also Drop).

Reserve exactly 96 logical pixels times each display scale at the monitor bottom. Caller must query Windows work area after success and must not subtract another taskbar band. Dock HWND registration does not resize its UI window. Original Shell_TrayWnd and Shell_SecondaryTrayWnd are enumerated; their class, physical rectangle, and visibility are journalled. The global public AppBar state is persisted. Auto-hide is temporarily enabled to release Explorer reservation; registration is accepted only when queried/set AppBar bounds exactly match the replacement band. If Explorer retains its prior reservation, takeover rolls back before any explicit taskbar hide. Third party AppBars consuming other edges also conservatively fail the strict geometry check.

Journal creation uses create_new and sync_all. A separate same executable watchdog opens the parent process before emitting a UUID-token ready file. Hiding waits for that ready file. PID plus creation time prevents PID reuse. Normal disable unregisters AppBars, restores global state and original visibility, then deletes the journal. Crash watchdog restores via fresh shell enumeration. Startup recovery rejects live owners and restores stale records. Explorer HWNDs are never persisted or reused. Polling refreshes reservation and re-finds shell windows. No administrator request, injection, or Explorer termination.

Tests cover replacement geometry (reject stacked reservation), per-display fullscreen edges, and PID-reuse identity. Tests were authored first. Initial execution was blocked because cargo is not in the shell PATH; toolchain discovery remains in progress. No live taskbar was hidden, no taskbar state modified, and no native takeover claims have been empirically validated.

Limitations: actual normal exit/crash/Explorer restart/multimonitor/DPI behavior requires a supervised integration test. Auto-hide transition can retain a small edge reservation on some Windows versions; strict validation intentionally rejects those configurations. Newly connected monitors require controller recreation by app layer. Secondary display visibility matching uses physical rectangle overlap and class; rearranging monitors during a crash can prevent a visibility match (global auto-hide state still restores). Fullscreen detection uses foreground window physical coverage, excludes desktop/shell and current process, and is not an exhaustive exclusive-mode detector. Calls are intended on the GUI thread that owns the registered dock windows. tick errors must immediately trigger disable in app integration. The watchdog cannot restore immediately if both processes are terminated or power is lost; startup recovery handles retained journals. Recovery journal is local app data and not hardened against same-user tampering.

Updated validation: `python tools/cargo_local.py test --no-default-features --test taskbar-policy` passed all 3 tests (0 failures). Module and Win32 declarations compiled and linked on Windows without invoking takeover. Tests import the module directly with library model types. Tests were written before implementation; initial attempt to execute failed due missing cargo PATH, so there was no observed semantic red test run.

Follow-up hardening: saved rectangles now identify the nearest physical monitor via MonitorFromWindow/GetMonitorInfo rather than potentially offscreen auto-hide taskbar geometry. Polling detects primary shell HWND/PID replacement and re-registers AppBars and auto-hide policy. Restoring visible taskbars uses SW_SHOWNOACTIVATE. Watchdog closes parent process handle if ready-file write fails. The monitor rearrangement limitation now concerns physical-monitor identity changes rather than auto-hide slide positions.

## Multi-monitor fullscreen review correction

Foreground-only detection was replaced with independent per-monitor front-to-back Z-order inspection (GetTopWindow / GW_HWNDNEXT). The first meaningful window intersecting that monitor decides its fullscreen status, so focusing an ordinary window on monitor B no longer reveals the dock over fullscreen monitor A. Invisible, minimized, own-process, tool windows, desktop/taskbar/menu/tooltip classes, and DWM-cloaked windows are excluded. DwmGetWindowAttribute is dynamically resolved once with a retained module reference, avoiding dependence on a DWM import library absent from the minimal GNU toolchain. Remaining limitation: this is geometric fullscreen/occlusion detection, not a claim to detect every exclusive display presentation mode.

Regression test was observed failing before the helper implementation; after implementation, `python tools/cargo_local.py test --no-default-features --test taskbar-policy` passes 4 tests. Cases include fullscreen A while normal B has higher Z order, and ordinary A covering fullscreen A. OpenProcess and related handle parameters now use raw pointer HANDLE representations; scoped extern-declaration warning allowances document layout-equivalent local repr(C) structs. No actual taskbar hide or native fullscreen simulation was performed.

## AppBar work-area integration correction

Root supervised live testing showed the former registered 220px WebView returned a negotiated96px rectangle but did not produce the required rcWork. This was a real failed integration check; negotiated AppBar rectangles alone are insufficient evidence. Microsoft documentation requires positioning the actual registered HWND and forwarding WM_WINDOWPOSCHANGED to ABM_WINDOWPOSCHANGED: https://learn.microsoft.com/en-us/windows/win32/shell/application-desktop-toolbars .

The implementation now creates one separate transparent native reservation window for each display on its own Win32 message-loop thread. It registers and positions that HWND at the96logical-pixel band, leaving the WebView geometry intact. The window is layered alpha-zero, transparent to input, a tool window, and nonactivating. Its window procedure forwards the AppBar activation/position lifecycle and handles close/destruction. disable removes each AppBar before closing its reservation HWND. The crash watchdog still restores Explorer, and dead-process reservation windows disappear with their owning process.

enable now validates actual GetMonitorInfo work rectangles after taskbar hiding, requiring four consecutive100ms successful samples within3seconds. Failure writes quickbar-native-diagnostic.txt and rolls back. tick also checks the actual work area. This supersedes the earlier report statement that the dock WebView HWND serves as the reservation. Public APIs remain unchanged. Pure tests compile/link and all4pass after this correction; the authoring subagent did not run live takeover. Root must repeat supervised normal-exit/crash tests before claiming native integration success.

## Toggle-session watchdog isolation and Explorer transition handling

Each watchdog ready marker is now named with its session UUID. The guard rereads the journal on every wait iteration and exits when the token differs, so disable/re-enable within250ms cannot attach an old guard to the new ownership session. All ready-marker cleanup is session-specific. Added a regression test for token matching and distinct marker paths; observed missing-helper failure first, then all5native policy tests passed.

While Explorer has no primary taskbar HWND, tick now returns all docks hidden and keeps ownership pending rather than treating old AppBar registration as a permanent failure. When the shell returns, it reapplies auto-hide, re-registers reservation HWNDs, hides matching taskbars, and retries actual work-area validation for up to2seconds, requiring three stable samples. This transition has compile/pure-test coverage only and still requires supervised Explorer-restart integration verification.

## Cross-process journal mutation serialization

Added a named Local Windows mutex keyed by canonicalized parent directory plus filename, normalized for case and path separators and hashed with stable FNV-1a. Acquisition is bounded to5seconds and accepts WAIT_ABANDONED; RAII releases the mutex and closes the handle. Startup recovery locks read/owner-check/restore/delete as one critical section. Parent-death watchdog recovery takes the same lock, rereads the current journal, validates its session token, then restores/deletes inside that critical section. New journal creation and normal disable restoration/deletion also use this lock. This prevents an older watchdog deleting a newer session journal during concurrent startup recovery. Watchdog lock timeouts retry while preserving the journal. Regression helper test was observed failing first; final6native policy tests pass. No live takeover was run for this change.
