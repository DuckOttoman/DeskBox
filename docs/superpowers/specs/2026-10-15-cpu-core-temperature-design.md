# CPU 核心温度采集与显示方案

## 目标与已授权范围
用真实核心温度替换当前被误认为 CPU 温度的 ACPI 热区显示。用户已同意独立采集进程，并要求系统状态小组件右键子菜单提供最低、最高、同时显示三种模式。

## 三种实现路径
1. 推荐：集成 LibreHardwareMonitorLib 的独立采集进程，仅启用 CPU，按需使用其当前支持的硬件访问组件。主程序保持普通权限。无需用户一直打开另一款监控软件，但需处理额外依赖、权限与传感器支持差异。
2. 读取用户已运行的硬件监控软件的公开接口：依赖较少，但功能依赖另一个程序一直运行，不作为默认实现。
3. 保留 ACPI：最轻，但无法满足真实核心温度与当前核心最小/最大值要求，不选用。

## 显示与配置
系统状态小组件右键 → CPU 温度 → 最低核心温度 / 最高核心温度 / 同时显示。当前项勾选，每个小组件单独保存，重启和布局备份后保留。默认最高核心温度。
最低/最高均为同一轮采样中各有效核心当前值的最小/最大值，不使用传感器运行期间历史 Min/Max。同时显示示例：最低 38°C · 最高 56°C。排除 CPU Package、距离温度上限、主板热区和平均温度等非独立核心读数；仅提供封装温度的机器明确标为 CPU 封装，核心模式显示不可用，不伪造核心范围。

## 采集与权限
独立采集进程只读取 CPU 温度，主程序通过有访问限制的本地通信接收带采样时间的结果；不让 WebView 页面直接访问特权接口。与现有刷新间隔一致，共享一次采集给多个系统状态组件。无系统状态组件时停止采集，退出时结束子进程。
所选正式依赖必须固定版本、校验来源并带许可证；安装包和替换更新包都包含所需组件。若需驱动或权限提升，安装/启用时清楚说明并由 Windows 显示必要权限提示，不更改系统安全设置。控制台隐藏，但不隐藏系统权限提示。不自动上传 GitHub。

## 失败与备用
采集进程失败、权限被拒绝或读数过期后清除核心温度，显示具体不可用原因，不能继续显示旧温度。ACPI 如可用则作为单独明确标注的备用信息，不能冒充最低/最高核心温度。

## 验证与交付
先测试筛选核心传感器、每轮最小/最大计算、非法读数、断连和过期，再验证菜单切换、持久化、多组件独立选择与真实采样刷新。最后编译、测试安装更新，交付安装包及替换更新包。真实硬件验证若需用户批准 Windows 管理员提示，则在实现准备好后执行；无法读取真实核心时明确报告，不能用测试数据声称采集成功。

## 审查结果
范围、瞬时值定义、异常处理、权限边界和交付内容已明确；尚未编写生产代码，用户已批准，并追加批准：安装版一次授权注册按需 Windows 服务；便携版独立提升采集进程权限，主程序不提升。
